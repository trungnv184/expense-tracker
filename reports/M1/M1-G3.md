## What was done
- `src/data/db.ts`: Dexie schema v1 (expenses, budgets, recurring, settings) and the TypeScript record types.
- Repositories: `expensesRepo` (add/get/update/remove/byMonth/all), `budgetsRepo` (all/set/clear/saveAll) and `settingsRepo` (currency, default USD).
- `errors.ts`: `StorageError`, `NotFoundError`, and `guard()`, which normalises Dexie failures.
- `bootstrap.ts` opens the database and requests `navigator.storage.persist()`. `main.tsx` renders the `StorageUnavailable` notice if the database can't be opened.

## Decisions
- Dexie re-wraps errors thrown inside transactions, so `guard()` recognises `NotFoundError` by name as well as by class.

## Follow-ups / known limitations
- The name-based check could treat a native IndexedDB `NotFoundError` DOMException as a missing record. This will be tightened in M2-G1 with an explicit marker on the domain error (verifier note).
- The REQ-014 e2e test writes straight to IndexedDB, because no UI writes data yet. Full UI persistence (expenses, budgets, recurring) is covered in M5-G2.
- REQ-015 performance at 5,000 rows is benchmarked in M5-G3.
