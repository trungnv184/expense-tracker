## What was done
- `src/domain/categories.ts`: the five fixed categories (id, label, icon, colour token), in order.
- `src/domain/money.ts`: `parseAmount` does string-based parsing into integer hundredths (ADR-002). Also `formatAmount` and `currencySymbol` (Intl, with a cached formatter per currency and locale), and `minorToDecimal`.
- `src/domain/dates.ts`: local-date helpers (month arithmetic, clamping a day to the month's length, validation, display names).
- `src/domain/validation.ts`: `validateExpense`, `validateBudget` and `validateRecurring`, each returning per-field errors.
- 45 unit tests, including a purity test that fails if domain code imports from data or ui.

## Decisions
- `parseAmount` is a little more lenient than the regex in §7: it accepts ".5", "12." and inner spaces, and treats a lone comma as the decimal separator. This is friendlier typing; the 2-decimal and positive-amount rules still apply.
- `playwright.config.ts` now uses `reuseExistingServer: false`. This is the follow-up from the M1-G1 report: every e2e run rebuilds, so tests never hit a stale preview server.

## Follow-ups / known limitations
- "1,000" is read as a decimal comma and rejected with "Use at most 2 decimals". The UI hint should say not to use thousands separators (M2-G1).
- Amounts above 1 billion are rejected with the generic "not a number" error.
