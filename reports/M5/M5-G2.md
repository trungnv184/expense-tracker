## What was done
- `vite-plugin-pwa` (generateSW) precaches the whole build (8 entries). The app has a web manifest and an SVG icon.
- A build-only Vite plugin injects a strict CSP meta tag (`default-src 'self'`, `connect-src 'self'`, `object-src 'none'` and so on).
- e2e tests:
  - `offline.spec.ts`: the full journey works offline.
  - `network.spec.ts`: no requests leave the origin or carry data, and the CSP is present.
  - `persistence.spec.ts`: expenses, budgets, recurring items and the currency survive a reload and a new page, all entered through the UI.

## Decisions
- The CSP is injected only into production builds, because the Vite dev server needs inline scripts for HMR.
- **Incident:** this goal was developed in a git worktree with `node_modules` symlinked in. `git add -A` committed the symlink, because `.gitignore` had `node_modules/` and a trailing slash doesn't match a symlink. Checking the branch out in the main tree then replaced the real `node_modules` with a self-referencing link and broke the running verifier.
  - Fix: the verifier was stopped, the symlink and `.flow/stop-guard.json` were untracked (commit 9c5c7f8), `.gitignore` now has `node_modules` without the slash, and `npm ci` restored the dependencies.
  - The whole suite was re-run and the goal re-verified. No source code was affected.
- The E2E tests now wait for the URL to change rather than for a toast, since a toast from the previous save can still be on screen and cause a race.

## Follow-ups / known limitations
- The network test listens with `page.on('request')`, so it doesn't see the service worker's own fetches. It will switch to `context.on('request')` in M5-G3.
- A real browser restart (persistent profile) isn't tested; IndexedDB persistence makes this low risk.
