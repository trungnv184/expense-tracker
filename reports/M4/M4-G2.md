## What was done
- `bootstrap()` runs `recurringRepo.generateDue()` before the first render. If generation fails, the error is logged and the app still starts; the rolled-back work is retried on the next open.
- `RecurringPage`: active definitions first, then stopped ones, each with its amount, category, day and start month. A Stop button opens a confirmation, and a notice shows how many expenses a new definition backfilled.
- `RecurringFormPage` handles create and edit. The start month is read-only when editing, and a note explains that changes apply to future months only. Validation covers amount, category, day (1–31) and start month.
- `ConfirmDialog` now uses `useId()` for its title id (follow-up from M2-G3).

## Decisions
- "Open the app again" in the tests means a real page reload, because a hash change doesn't re-run startup.
- A planned e2e test that tried to force a generation failure with a malformed definition was replaced by unit tests: the malformed data wouldn't actually have caused a failure.

## Follow-ups / known limitations
- The mockup's notice for expenses added when the app opens is not shown; only the count after creating a definition is. The mockup map lists it as nice-to-have.
- The "N added" notice comes from router history state and can reappear if the user navigates back.
