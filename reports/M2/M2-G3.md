## What was done
- `ExpenseFormPage` now handles both `/expenses/new` and `/expenses/:id`. In edit mode it prefills the form, shows "Save changes" and a Delete button, and runs the same validation as adding.
- `ConfirmDialog`: a native `<dialog>` opened with `showModal()` (Esc cancels), with a fallback for jsdom.
- If an expense no longer exists (on load, save or delete), the app shows "Expense no longer exists" and goes back to the list.
- e2e/expense-list.spec.ts: the clear-filter check now retries until the page settles (follow-up from M2-G2).

## Decisions
- One form component handles add and edit, so validation can't drift between them.
- The `git commit` call was split from a command containing `grep -n`, because a local hook reads `-n` as no-verify. No hooks were bypassed.
